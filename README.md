# 一事

> 一次，只做一件事。

一款本地优先的个人专注与时间管理工具，四个板块：专注（计时 + 事项）、App（时间记录与分类）、历史记录（日历 + 时间线 + 系统日历同步）、统计（七项指标）。视觉为米白 + 珊瑚橙 + 大圆角的极简现代风，深浅色模式完整适配。

（原名「老钱ToDo」，2.0 起更名为「一事」）

## 打开运行

1. Android Studio 打开本目录（File > Open，选 `ToDo` 文件夹）
2. 等待 Gradle Sync 完成（首次较慢，需下载依赖）
3. 连接 Android 手机（Android 8.0 / API 26 以上，开启 USB 调试），点 Run

构建环境：JDK 17+（AS 自带 JBR）、Android SDK 34（AS 会自动提示安装）、Gradle 8.9（wrapper 已内置）。

## 功能

| 板块 | 内容 |
|---|---|
| 专注 | 事项清单可自定义添加/删除，点一下开始正计时；通知栏与锁屏常驻显示，支持暂停/继续/结束，手表与蓝牙耳机也能控制；结束后自动入账 |
| App | 读取系统使用记录：今日总时长、时间分布（按分类）、今日时间轴（按分类合并的时间块）、7 天趋势、使用排行；可把时间轴按分类同步到系统日历（标题如「学习 · 45m」） |
| 历史 | 自绘月历（默认收起为一周，有记录的日期显示标记点）+ 当天时间线；支持手动添加、编辑、删除记录；专注 App 的自动记录也可编辑（转为一条记录）与删除（隐藏，可撤销）；可一键同步当天全部记录到系统日历（幂等不重复），编辑/删除会联动更新日历事件，默认写入"工作"日历 |
| 统计 | 本月专注（含日均与环比）、今日有效专注（计时 ∪ 专注 App 使用，已去重）、项目分布（环形图 + 百分比）、专注时段（柱状图）、每日趋势与年度趋势（平滑曲线），均支持切换查看周期 |
| 数据备份 | 一键导出/导入全部数据为 JSON 文件：专注记录、事项、时间分类、分类规则、专注 App、日历映射与设置项；卸载重装或换机后恢复，导入前先体检再确认，坏文件绝不动数据 |
| 自动备份 | 在设置里选一个目录，之后每次专注结束、每天首次打开 App 时自动写一份 JSON（按日期命名，保留最近 7 份），不申请任何存储权限 |

## 关键设计

- **计时存活**：前台服务（`TimerService`）+ 每秒刷新内存状态。计时用 `SystemClock.elapsedRealtime()` 差值，改系统时间不影响准确性
- **通知计时显示**：通知必须用媒体样式（`MediaStyle`）才能在 vivo 锁屏显示，但媒体样式不支持系统 chronometer（不走时），因此时间写在正文并由服务每秒刷新；同时用 `AlarmManager.setAndAllowWhileIdle` 每 30 秒唤醒一次兜底——**进程被 ROM 冻结时 Handler 会停，但系统闹钟仍能叫醒进程刷新通知**，保证时间不会一直卡住
- **崩溃恢复在进程级**：从存档恢复计时放在 `FocusApplication.onCreate`（每进程一次），不能放 Activity（后台返回时 Activity 可能重建，会用旧存档覆盖内存中正在走的计时，表现为时间倒退）。持久化存的是运行段的 `elapsedRealtime` 起点，进程被杀重建后可精确补回，只有设备重启才退化为暂停
- **服务重建自恢复**：`onStartCommand` 收到空 action 时从存档恢复并重建前台通知，被杀后能自己爬起来
- **targetSdk 34**：刻意不升 35，规避 Android 15 对 `dataSync` 前台服务 24 小时 6 小时的限制
- **自动记录不可删，只能隐藏**：专注 App 的自动记录是从系统使用记录实时派生的，没有自己的行。所以「删除」落到 `hidden_usage_segments` 表（记区间，按「与原段重叠过半」匹配），可撤销；「编辑」则是转成一条真实记录（原段一并隐藏）。隐藏只作用于历史时间线，App 页作为「系统事实」视图不变
- **统计**：七项指标全部由 Room 聚合 SQL 产出，图表用 Compose Canvas 自绘，零图表库依赖
- **图表可读性约定**：Y 轴步长从「好读的时间档位」（5 分 ~ 10 天）里挑，单位按整条轴统一切换（步长是整小时就全用小时，否则全用分钟），不出现 167分/333分 这类三等分产物；数值标注带避让，最高点优先占位，能放几个放几个；年度趋势用柱状（12 个离散月份），每日趋势用折线 + 平均虚线（空日按 0 补）
- **通知锁屏显示**：通知采用媒体样式（`MediaStyle` + `MediaSession`）而非普通样式。原因是 vivo/OriginOS 会把普通前台服务通知挡在锁屏外（渠道重要性已为 HIGH 仍然不显示），而媒体通知走锁屏的媒体控制面板这条系统特权通道，能正常显示；会话回调已接到暂停/继续/结束逻辑，锁屏按钮可用
- **通知渠道 ID 的坑**：Android 渠道一旦创建，重要性与锁屏可见性**无法通过代码修改**，改属性必须换新的渠道 ID；但**绝不能把当前正在使用的渠道也加入清理列表**，否则 startForeground 会因渠道缺失抛异常直接崩溃
- **蓝牙/手表媒体控制**：媒体会话会把手表、耳机识别为媒体控制器，可直接暂停/继续/结束计时。**关键**：暂停时必须把 `PlaybackState` 同步为 `STATE_PAUSED`（恢复时切回 `STATE_PLAYING`），否则设备端一直显示暂停键、发来的还是暂停命令，表现为"从设备端无法恢复计时"
- **自动备份**：走 SAF 树 URI（`ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission`），不需要任何存储权限（targetSdk 34 下 `MANAGE_EXTERNAL_STORAGE` 基本拿不到）。触发点是「专注结束」与「每天首次打开」，文件名带 ISO 日期、同天覆盖、只保留最近 7 份；目录被删或权限失效时设置页会如实显示「上次备份失败」，不静默
- **数据备份**：`BackupManager` 把业务数据与设置导出为 JSON（系统文件选择器选保存位置）。导入遵循三条硬规则：**先认领**（`app` 字段不是「一事」的文件一律拒绝）、**先解析后落库**（整份文件校验通过才在单事务里清表写入，中途失败整体回滚）、**表按 presence 替换**（备份里没有的段保持原样，兼容老版本备份）。恢复日历映射可在确认框里选择是否保留。数据完全本地，不走网络，支持卸载重装/换机

## 国产 ROM 后台保活（必做）

国产 ROM（vivo / OriginOS、小米、华为等）在息屏或切后台后会冻结进程，导致通知里的时间停止刷新。首次安装后建议引导用户：

1. 设置 > 电池 > 后台耗电管理 > 一事 > 允许后台高耗电
2. 系统设置里关闭该应用的电池优化
3. 通知权限保持开启（锁屏通知、悬浮通知）

## 更新日志

> **版本号说明**：2.0 起为对外发布编号。1.0–1.3 属内部开发期；原先的 1.4 曾以「1.4」出过测试包，现统一记为 2.0，其后顺延（1.5→2.1、1.6→2.2、1.7→2.3、1.8→2.4、1.9→2.5、1.10→2.6）。`versionCode`（机器用）未回退，仍连续递增。
> 每条日志开头的一句话是这一版的升级点，细项在下面。

### 2.7 · 2026-09-25
**正在使用的 App 不再被算成「一直用到今天 0 点」。**

- 修复：读当天 App 使用区间时，最后一个还开着的片段被截止到「当天结束」（次日 0 点）而不是「现在」，于是时间轴上多出一条延伸到未来的块，同步到日历后就是一个横跨到 0 点的「其他」事件
- 现在统一截止到当前时刻（与「专注 App 时段」那条路径同口径）；「今天」的形状会随时间继续生长，而不是先画到午夜
- 已存在的错误事件不用手动清：重新同步当天（或等自动同步）会整体重建
- 「一事」自己不再计入使用统计：排行、时间轴、今日总时长里都不会再出现它（看 App 页时前台的就是它自己）
- 图标资源改名 `ic_launcher_yishi_v2` / `ic_launcher_foreground_v2`：国产 ROM 按「包名 + 图标资源」缓存 App 图标，锁屏与系统日历会一直沿用旧的老钱ToDo 图标，换资源名是能强制刷新的手段

### 2.6 · 2026-09-25
**系统自动记下的时间段不再只能看，可以改成自己的记录，也可以删掉（可撤销）。**

- 「专注 App 的自动记录」不再是只读的，右侧 ⋯ 菜单新增「编辑」与「删除」
  - **编辑** ＝ 转成一条真实记录：名称与起止时间都能改，转完能继续编辑 / 删除 / 同步到日历，也进入统计的项目分布
  - **删除** ＝ 隐藏：自动记录由系统使用记录实时派生，改不了源数据，所以删除记在本地隐藏表（`hidden_usage_segments`），下次派生时不再出现；底部浮条 6 秒内可撤销
- 数据库升级 v6 → v7（新增 `hidden_usage_segments`，`MIGRATION_6_7`）
- 备份格式升到 v3：隐藏记录随备份迁移，老备份（v1/v2）仍可导入
- 底部「撤回浮条」抽成共用组件（日历同步撤回与自动记录撤销共用）
- 口径说明：隐藏只作用于「历史」时间线；App 页是「系统事实」视图，仍照常显示

### 2.5 · 2026-09-25
**统计图表重做刻度与标注，纵轴从「500分/333分/167分」变成「2h/4h/6h/8h」，年度趋势一眼看清哪个月最投入。**

- **Y 轴刻度重做**：原来把最大值抬到 1/2/3/5×10ⁿ 再三等分，得到 500分/333分/167分 这种没有语义的刻度（年度图上是 167h/111h/56h）；改为从「好读的时间档位」（5分~10天）里挑步长，单位按整条轴统一（步长是整小时就写 2h/4h/6h/8h，否则写分钟）
- **数值标注防重叠**：不再「有值点 ≤6 全标、否则只标最大的 5 个」（并列最大的几个恰好在相邻天就会撞在一起），改为全体有值点参与，最高点优先占位，其余按 x 从左到右逐个尝试，跟前一个挤上就跳过
- **折线填充减淡**：起手透明度 0.30 → 0.16，让折线而非色块当主角
- **每日趋势补齐空日**：没有记录的日子按 0 计入（此前只画有记录的日子，点的位置会随记录数漂移），并新增一条平均值虚线 + 「平均 xh ym」
- **年度趋势改柱状图**：12 个月份是离散量，平滑曲线会把 1–7 月的 0 和 9 月的尖峰拟合成一道并不存在的缓坡；柱状图只给最高月标数值，柱顶改为紧凑时长
- **柱状图不再每根标数字**：只标最高的一根（原来每根都挂一个无单位裸数字），量级交给 Y 轴
- 数据库结构不变（v6）

## 备注

- **构建目录隔离**：项目位于共享目录时，Linux 与 Windows 切勿共用 `build/`（Kotlin 增量编译缓存的路径格式会冲突）。命令行构建用环境变量把产物指到本地磁盘：`export YISHI_LINUX_BUILD_DIR=$HOME/.yishi-build`，产物与缓存都会落到该目录；Android Studio 侧不设该变量，继续用项目内默认 `build/`
- 本项目刻意不用 version catalog（`libs.versions.toml`）：共享目录/部分文件系统对长文件名有限制，catalog 生成的访问器类名会超限导致构建失败，直接写依赖最稳
- 数据库升级：`AppDatabase` 当前 version 为 7，含 6 条迁移（1→2 日历映射、2→3 事项、3→4 专注 App、4→5 时间分类、5→6 时间块映射、6→7 隐藏的自动记录）；后续改实体结构需新增 Migration
- 图表配色跟随主题暖色系（珊瑚橙/暖黄/松绿/暖棕），在 `Charts.kt` 的 `chartColors` 里可调
