# 一事

> 一次，只做一件事。

一款本地优先的个人专注与时间管理工具，三个板块：专注（计时 + 事项）、历史记录（日历 + 时间线 + 系统日历同步）、统计（七项指标）。视觉为米白 + 珊瑚橙 + 大圆角的极简现代风，深浅色模式完整适配。

（原名「老钱ToDo」，v1.4 起更名为「一事」）

## 打开运行

1. Android Studio 打开本目录（File > Open，选 `ToDo` 文件夹）
2. 等待 Gradle Sync 完成（首次较慢，需下载依赖）
3. 连接 Android 手机（Android 8.0 / API 26 以上，开启 USB 调试），点 Run

构建环境：JDK 17+（AS 自带 JBR）、Android SDK 34（AS 会自动提示安装）、Gradle 8.9（wrapper 已内置）。

## 功能

| 板块 | 内容 |
|---|---|
| 专注 | 事项清单可自定义添加/删除，点一下开始正计时；通知栏与锁屏常驻显示，支持暂停/继续/结束，手表与蓝牙耳机也能控制；结束后自动入账 |
| 历史 | 自绘月历（可折叠为一周，有记录的日期显示标记点）+ 当天时间线；支持手动添加、编辑、删除记录；可一键同步到系统日历（幂等不重复），编辑/删除会联动更新日历事件，默认写入"工作"日历 |
| 统计 | 本月专注（含日均与环比）、今日/累计、项目分布（环形图 + 百分比）、专注时段（柱状图）、每日趋势与年度趋势（平滑曲线），均支持切换查看周期 |
| 数据备份 | 一键导出/导入全部数据（专注记录、事项、日历映射）为 JSON 文件，卸载重装或换机后恢复 |

## 关键设计

- **计时存活**：前台服务（`TimerService`）+ 每秒刷新内存状态。计时用 `SystemClock.elapsedRealtime()` 差值，改系统时间不影响准确性
- **通知计时显示**：通知必须用媒体样式（`MediaStyle`）才能在 vivo 锁屏显示，但媒体样式不支持系统 chronometer（不走时），因此时间写在正文并由服务每秒刷新；同时用 `AlarmManager.setAndAllowWhileIdle` 每 30 秒唤醒一次兜底——**进程被 ROM 冻结时 Handler 会停，但系统闹钟仍能叫醒进程刷新通知**，保证时间不会一直卡住
- **崩溃恢复在进程级**：从存档恢复计时放在 `FocusApplication.onCreate`（每进程一次），不能放 Activity（后台返回时 Activity 可能重建，会用旧存档覆盖内存中正在走的计时，表现为时间倒退）。持久化存的是运行段的 `elapsedRealtime` 起点，进程被杀重建后可精确补回，只有设备重启才退化为暂停
- **服务重建自恢复**：`onStartCommand` 收到空 action 时从存档恢复并重建前台通知，被杀后能自己爬起来
- **targetSdk 34**：刻意不升 35，规避 Android 15 对 `dataSync` 前台服务 24 小时 6 小时的限制
- **统计**：七项指标全部由 Room 聚合 SQL 产出，图表用 Compose Canvas 自绘，零图表库依赖
- **通知锁屏显示**：通知采用媒体样式（`MediaStyle` + `MediaSession`）而非普通样式。原因是 vivo/OriginOS 会把普通前台服务通知挡在锁屏外（渠道重要性已为 HIGH 仍然不显示），而媒体通知走锁屏的媒体控制面板这条系统特权通道，能正常显示；会话回调已接到暂停/继续/结束逻辑，锁屏按钮可用
- **通知渠道 ID 的坑**：Android 渠道一旦创建，重要性与锁屏可见性**无法通过代码修改**，改属性必须换新的渠道 ID；但**绝不能把当前正在使用的渠道也加入清理列表**，否则 startForeground 会因渠道缺失抛异常直接崩溃
- **蓝牙/手表媒体控制**：媒体会话会把手表、耳机识别为媒体控制器，可直接暂停/继续/结束计时。**关键**：暂停时必须把 `PlaybackState` 同步为 `STATE_PAUSED`（恢复时切回 `STATE_PLAYING`），否则设备端一直显示暂停键、发来的还是暂停命令，表现为"从设备端无法恢复计时"
- **数据备份**：`BackupManager` 把专注记录、事项、日历映射导出为 JSON（系统文件选择器选保存位置），导入时清空后整体恢复。数据完全本地，不走网络，支持卸载重装/换机

## 国产 ROM 后台保活（必做）

国产 ROM（vivo / OriginOS、小米、华为等）在息屏或切后台后会冻结进程，导致通知里的时间停止刷新。首次安装后建议引导用户：

1. 设置 > 电池 > 后台耗电管理 > 一事 > 允许后台高耗电
2. 系统设置里关闭该应用的电池优化
3. 通知权限保持开启（锁屏通知、悬浮通知）

## 权限清单

| 权限 | 用途 | 触发时机 |
|---|---|---|
| POST_NOTIFICATIONS | 前台服务通知 | 点"开始"时申请（Android 13+） |
| WRITE/READ_CALENDAR | 同步到系统日历（读写一起申请，查询日历需要 READ，写入事件需要 WRITE） | 历史记录点同步按钮时申请 |

## 目录结构

```
app/src/main/java/com/example/focus/
├── MainActivity.kt            冷启动恢复计时 + 入口
├── data/
│   ├── db/                    Room：FocusSession / FocusDao（全部统计 SQL）/ AppDatabase
│   ├── repo/                  SessionRepository
│   ├── prefs/                 TimerStateStore（计时状态持久化）
│   └── sync/                  CalendarSyncManager（日历幂等同步）
├── service/
│   ├── TimerService.kt        前台计时服务（开始/暂停/继续/结束 + 落库）
│   └── TimerStateHolder.kt    进程内计时状态（StateFlow）
└── ui/
    ├── components/            MonthCalendar（自绘月历）/ Charts（环形饼图/平滑曲线/柱状图）
    ├── todo/                  待办板块（首页）
    ├── history/               历史板块（日历 + 时间线 + 同步）
    ├── stats/                 统计板块（七项指标）
    ├── permissions/           权限中心
    └── theme/                 Material3 主题
```

## 备注

- **构建目录隔离**：项目位于共享目录时，Linux 与 Windows 切勿共用 `build/`（Kotlin 增量编译缓存中的路径格式会冲突，Windows 会把 `/mnt/...` 当作相对路径而报错）。命令行构建请加环境变量 `YISHI_LINUX_BUILD=1`，产物会落到 `.build-linux/`；Android Studio 侧不用该变量，继续用默认 `build/`
- 本项目刻意不用 version catalog（`libs.versions.toml`）：共享目录/部分文件系统对长文件名有限制，catalog 生成的访问器类名会超限导致构建失败，直接写依赖最稳
- 数据库升级：`AppDatabase` 当前 version 为 3，已含 `MIGRATION_1_2`（日历映射表）、`MIGRATION_2_3`（待办表）；后续改实体结构需新增 Migration
- 图表配色跟随主题暖色系（珊瑚橙/暖黄/松绿/暖棕），在 `Charts.kt` 的 `chartColors` 里可调
